## <a id="02"></a>02 새 문서

1. 맞는 묶음 폴더에 kebab-case `.md`로 만든다. 템플릿 문서는 `templates/<템플릿>.md`다.
2. 03절의 빈 틀에서 시작한다.
3. frontmatter를 채운다.
   - `name`은 영어 이름이다. 문서 제목과 사이드바 목록에 쓰인다.
   - `label`은 한글 이름이다. 사이드바에서 이름에 마우스를 올리면 뜬다.
   - `group`은 폴더에 맞는 묶음 이름이다(01절 표).
     새 묶음을 만들면 폴더도 새로 만들고, `for-humanity.config.mjs`의 `navigation`에 순서를 더한다.
   - `order`는 묶음 안의 순서다. 10 단위로 매겨 사이에 끼울 자리를 남긴다.
4. 세 곳에 한 줄씩 더한다.
   - [문서 홈](../README.md)의 문서 표
   - [AGENTS.md](https://github.com/minu-ha/uoo/blob/master/AGENTS.md)의 "언제 무엇을 읽나" 표. 그 문서를 읽을 일이 있을 때만 더한다
   - 루트 [README.md](https://github.com/minu-ha/uoo/blob/master/README.md)의 `document/` 칸. 루트 README를 고치면 번역본도 같이 고친다(07절)

## <a id="03"></a>03 빈 틀

```markdown
---
name: {영어 이름}
label: {한글 이름}
group: {묶음}
order: {묶음 안 순서}
---

{이 문서가 답하는 것 한두 줄. 여기 없는 것은 어디 있는지 링크}

## <a id="00"></a>00 한눈에

{절마다 무엇을 답하는지 적은 표}

::part[{가름}]

## <a id="01"></a>01 {절}

{본문}

### <a id="01.A"></a>01.A {소제목}

{본문}
```

- `#` 제목은 쓰지 않는다. `name`이 문서 제목이 된다.
- 첫 `##` 앞의 글이 문서 머리다. 이 문서가 답하는 것을 한두 줄로 적고, 여기 없는 것은 어디 있는지 링크한다.

## <a id="04"></a>04 짜임

- 목차는 쓰지 않는다. for-humanity가 `##`와 `###`로 On this page 목차를 만든다.
- 절은 두 자리 번호로 `## <a id="01"></a>01 이름`처럼 쓴다. 소제목은 절 번호에 대문자를 붙여 `### <a id="01.A"></a>01.A 이름`처럼 쓴다.
  번호는 제목 글과 앵커에 함께 적는다.
- **앵커가 번호 링크를 지킨다.** for-humanity는 제목 글로 id를 만든다(`01 이름`이면 `01-이름`). 그래서 제목 글을 고치면 id도 바뀐다.
  제목 안에 번호와 같은 `<a id>`를 두면, 다른 곳에서 언제나 번호로 가리킬 수 있다(`razor.md#03`).
  앵커를 제목 위에 따로 한 줄로 두면 빈 문단이 되어 앞 절 끝에 붙는다. 그래서 제목 줄 안에 둔다.
- `####` 아래 제목에는 번호도 앵커도 달지 않는다. 목차에 들지 않는 작은 제목이다.
- `00`은 한눈에 자리다. "절 | 무엇을 답하나" 표를 두어 처음 여는 사람이 길을 찾게 한다. 이 문서에 걸린 질문은 [Open items](../questions/open-items.md)로 보낸다.
- 절이 많으면 몇 절씩 가름으로 묶는다. 가름을 여는 첫 절의 제목 바로 위에 `::part[이름]`을 한 줄 둔다.
  사이트는 그 앞에 가름 머리를 달고, On this page 목차도 가름마다 끊는다.
- 00 한눈에는 가름 밖에 둔다. 문서 끝의 확인 안 된 것, 자주 틀렸던 것, 참고 링크는 `기록` 가름으로 묶는다.
- 글 안에서는 제목에 보이는 번호로 "03절", "05.D절"처럼 가리킨다. 다른 문서는 문서 이름으로 링크하고 절을 붙인다(`[Razor](../scripting/razor.md#03) 03절`).
- 절을 넣거나 빼면 번호와 앵커를 함께 고친다. 그 번호를 가리키던 곳도 저장소 전체에서 찾아 고친다.
  AGENTS.md와 스크립트 주석(`part 5`)도 절 번호를 쓴다. `git grep -n -e '05.H' -e 'part 5'`로 찾는다.

## <a id="05"></a>05 문장

읽는 사람이 한 번에 알아듣게 쓴다. 문서는 메모가 아니라 글이다.

- **한 문장에는 한 가지만 쓴다.** 쉼표와 괄호로 이어 붙인 긴 문장은 둘이나 셋으로 나눈다.
- **명사만 늘어놓지 않는다.** "회복 실패 시 재시도 판단"보다 "회복이 실패하면 다시 시도할지 정한다"처럼 동사가 있는 문장으로 쓴다.
  목록의 항목도 되도록 문장으로 쓴다. 표의 칸은 짧은 구로 써도 된다.
- **가운뎃점(`·`)을 쓰지 않는다.** 둘을 잇는 것은 "A와 B", 셋 이상은 "A, B, C"처럼 쉼표로 늘어놓는다. 제목, 표, 목록, 라벨도 같다.
- **빗금(`/`)으로 낱말을 잇지 않는다.** "A나 B", "A 또는 B"로 쓴다. 경로, 명령, 값처럼 원래 빗금이 든 것은 그대로 둔다.
- **괄호는 짧은 보충에만 쓴다.** 괄호 안에 괄호를 넣지 않는다. 문장 하나가 통째로 괄호에 들어가면 괄호를 풀고 따로 쓴다.
- **화살표(`→`)는 표, 흐름, 대응 목록에만 쓴다.** 문장 안에서는 "그러면", "그래서", "에서 ... 으로"처럼 말로 쓴다.
- **결론을 먼저 쓴다.** 규칙이나 결정을 먼저 적고, 이유는 그 뒤에 적는다. 언제 무엇을 했는지 하는 경위는 기록 가름이나 날짜 붙은 한 줄로 줄인다.
- **같은 것은 같은 말로 부른다.** 한 문서에서 "루프"라 했으면 다른 곳에서 "스크립트 본체"라 바꿔 부르지 않는다.
  저장소에서 쓰는 말은 아래 표를 따른다.
- **고유한 이름은 원래 표기를 지킨다.** 게임의 스킬과 주문(Discordance, Greater Heal), Razor 명령(`findtype`), 파일과 변수는 그대로 쓴다.
  그 밖의 말은 한국어로 쓴다. 어색한 직역보다 익숙한 영어 용어가 나으면 영어를 쓴다.
- **숫자에는 단위를 붙인다.** 초, ms, 칸, 포인트처럼 적는다. 날짜는 `2026-10-11`처럼 쓴다.
- **강조는 아낀다.** 굵게는 한 문단에 한 번 정도, 놓치면 안 되는 문장에만 쓴다.
- 문체는 "~다"로 끝나는 평서문이다. 할 일도 "~한다"로 쓴다.

| 말 | 뜻 |
| --- | --- |
| 루프 | 핫키 하나로 켜 두는 메인 스크립트(`script/combat/*`, `script/gather/*`) |
| 패스 | 루프가 `while not dead`를 한 바퀴 도는 것 |
| 모듈, 블록 | `module/`의 파일 하나. 루프 안에서는 그 파일에서 온 코드 묶음을 블록이라 부른다 |
| 레시피 | 루프 하나를 어떤 모듈로 어떤 설정으로 조립할지 적은 `recipe/` 파일 |
| 템플릿 | 캐릭터의 스킬 구성(Bard Necro, Lumberjack PvP 같은) |
| 교전 | `var__fighting`이 1인 동안. 사거리 안에 고른 적이 있다 |

고쳐 쓴 예를 둔다.

| 고치기 전 | 고친 뒤 |
| --- | --- |
| 회복·실패·재시도 분기 | 회복, 실패, 재시도 분기 |
| 시전 중 큐 대기 후 상태 판독(설정 시) | `settle_first`가 1이면, 시전과 아이템 큐가 끝난 뒤 상태를 읽는다 |
| 바/오버헤드 미표시 | 쿨다운 바나 머리 위 알림이 뜨지 않는다 |

## <a id="06"></a>06 Markdown

- 본문은 GFM Markdown이다. 문단, 목록, 표, 코드, 인용(`>`)을 쓴다. 원시 HTML은 제목 앵커와 아래 강조 예외에만 쓴다.
- 강조가 문장부호나 코드로 끝나고 바로 한글이 붙으면 CommonMark가 강조로 읽지 않는다(`**(A OR B)**다`가 별표째 보인다).
  이럴 때는 `<strong>…</strong>`로 쓴다.
- 범위의 `~`는 `\~`로 쓴다. GFM은 한 문단 안의 `~` 두 개를 취소선으로 읽는다(`3~5초, 7~9초`).
- 코드 밖의 `*`, `_`, `[`, 그리고 영문자 앞의 `<`는 `\`로 막는다. 식별자와 값은 코드(`var__fighting`)로 쓰면 막을 필요가 없다.
- 큰따옴표와 `--`는 사이트에서 둥근 따옴표와 대시로 바뀐다. 서버 문장처럼 원문 그대로 보여야 하는 것은 코드로 쓴다.
- 코드 블록에는 코드, 의사 코드, 파일 트리만 쓴다. 칸을 맞춰야 하는 것은 표로 쓴다.
- Razor 코드 블록에는 언어를 달지 않는다(` ``` `만). 사이트의 코드 강조(Shiki)에는 Razor 문법이 없어서 `razor`를 달아도 색이 없다.
- 인용과 확인 표시는 [Workflow](workflow.md#01.C) 01.C절대로 쓴다. "인게임 확인됨"과 "확인되지 않았다"를 그 글자 그대로 쓰면 확인 알약으로 보인다.
  뒤에 날짜가 붙으면 날짜까지 알약이 되고(`인게임 확인됨 2026-09-28`), 괄호로 감싸면 괄호 없이 보인다. 코드, 링크, 제목 안에서는 바뀌지 않는다.
  알약 문구는 `for-humanity.config.mjs`의 `status`에 있다.
- `#e80030`처럼 색 값만 든 인라인 코드에는 색 칩이 붙는다.
- 다른 문서는 상대 경로 `.md`로 링크한다. `document/` 밖의 파일(AGENTS.md, `script/`, `util/` 같은)은 GitHub 주소로 링크한다
  (`https://github.com/minu-ha/uoo/blob/master/<경로>`). for-humanity는 문서 폴더 밖을 가리키는 상대 링크를 사이트 주소로 바꾸지 못해서 그 링크가 끊긴다.

## <a id="07"></a>07 언어와 번역본

- 문서와 답변은 한국어로 쓴다. 스크립트 안 주석은 영어로 쓴다.
- 사람이 처음 보는 README는 영어가 원본이다. 번역본은 `language/`에 `<무엇>.<언어>.md`로 둔다.
  `language/README.ko.md`는 루트 README의 번역본이고, `language/config.ko.md`는 `config/README.md`의 번역본이다.
- `document/`는 예외다. 홈 `document/README.md`도 다른 문서처럼 한국어로 쓰고, 번역본을 두지 않는다.
- 원본 맨 위에는 번역본 링크를, 번역본 맨 위에는 원본 링크를 둔다. 원본을 고치면 번역본도 같은 커밋에서 고친다.

## <a id="08"></a>08 한 사실은 한 곳에

- 같은 내용을 두 문서에 쓰지 않는다. 한 곳을 정본으로 두고, 다른 곳은 절 번호로 링크한다.
  두 곳에 쓰면 한쪽만 고쳐지고, 어느 쪽이 맞는지 모르게 된다. overheads.md의 옛 hue 표가 그렇게 틀렸다.
- 어느 문서가 무엇의 정본인지는 [문서 홈](../README.md)의 표 한 곳에 둔다. 문서를 새로 만들거나 정본을 옮기면 그 표를 고친다.
- 규칙도 마찬가지다. 에이전트가 언제나 지킬 규칙과 커밋 규칙은 AGENTS.md에만 두고, 나머지 규칙은 이 문서들에만 둔다.
  AGENTS.md는 규칙을 한 줄로 부르고 정본 절로 링크할 뿐, 내용을 옮겨 적지 않는다.
- 템플릿 문서에는 **그 템플릿이 내린 판단**만 둔다. 서버 규칙이나 문법처럼 다른 템플릿에서도 쓰는 내용이 생기면 공통 문서로 옮기고 링크를 남긴다.

## <a id="09"></a>09 흐름도

- 흐름도는 ` ```mermaid ` 코드 블록에 mermaid 원문을 쓴다. for-humanity가 빌드할 때 beautiful-mermaid 격자 렌더러로 SVG를 그린다.
  격자 렌더러라서 mermaid 문법이 전부 되지는 않는다.
- 잘 되는 것은 `flowchart TD` 사슬과 나무, `flowchart LR` 판단 사슬(`예` 사슬을 윗줄로), `sequenceDiagram`이다.
- 라벨에 괄호를 넣지 않는다. 렌더러가 괄호에서 글을 잘라 낸다. 긴 라벨은 `<br>`로 줄을 나눈다.
- 선 라벨은 한 낱말로 쓴다(`-- 예 -->`). 띄어 쓰면 격자가 빈칸을 선으로 채워서 라벨이 둘로 갈린다.
- 되돌아가는 선과 라벨 달린 합류선은 엉킨다. 그림이 크거나 엉키면 여러 장으로 쪼갠다([Bard Necro](../templates/bard-necro.md#05.A) 05.A절).
- 폭은 140칸 안쪽으로 둔다. 넘치면 `LR`을 `TD`로 바꾸거나 둘로 나눈다.

::part[확인]

## <a id="10"></a>10 끝낼 때 확인

- 한 줄은 200자까지다(`.editorconfig`의 `max_line_length`). 넘으면 코드 밖의 빈칸에서 줄을 바꾸고, 되도록 문장 끝에서 바꾼다.
  문단 안의 줄바꿈은 빈칸 하나로 보이므로 화면은 달라지지 않는다. 표의 줄과 코드 블록 안은 바꾸지 않는다.
- 05절대로 썼는지 다시 읽는다. 가운뎃점은 `git grep -n '·' -- document`로 찾는다.
- `pnpm check`를 돌린다. 문서 사이트를 만들고(`pnpm docs:build`), 끊긴 링크와 앵커, 번호 제목의 앵커를 검사한다(`node util/check-docs.mjs`).
- `pnpm docs:dev`로 열어 본다. 밝은 테마와 어두운 테마, 폭 1024와 390에서 가로로 밀리는 곳이 없는지, 흐름도가 그려지는지 본다.
