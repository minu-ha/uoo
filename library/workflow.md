## 1. 근거

### 1.1 우선순위

사용자 요청 > [AGENTS.md](../AGENTS.md) 와 `library/` 의 규칙 문서 > 같은 폴더의 기존 스크립트 > 공식 위키.

### 1.2 참고 사이트

| 용도                                            | 링크                                          |
|-------------------------------------------------|-----------------------------------------------|
| Outlands Razor 문법 (확장 명령 포함, 1순위)     | <https://wiki.uooutlands.com/Razor_Scripting> |
| 게임 메커니즘·아이템·몹                         | <https://wiki.uooutlands.com/>                |
| Razor CE 기본 문법 (Outlands가 포크한 원본)     | <https://www.razorce.com/guide/>              |
| 스크립트 라이브러리 (Jaseowns 등 공개 스크립트) | <https://outlands.uorazorscripts.com/>        |
| Storage Shelf 로드아웃 스크립트 생성            | <https://www.outlandsbutler.com/>             |
| 공식 포럼                                       | <https://forums.uooutlands.com/>              |

문법이 애매하면 추측하지 말고 위키를 읽는다. Outlands Razor 는 Razor CE 에 없는 명령이 많다 ([razor.md](razor.md)).

### 1.3 숫자는 인용한다

게임 숫자 (공식, 쿨다운, 확률)는 추측하지 않는다.

| 숫자                   | 어디서                                                                                   |
|------------------------|------------------------------------------------------------------------------------------|
| 바드, 네크로, 소환수   | [bard-necro-handbook.md](bard-necro-handbook.md)                                         |
| PvP 규칙               | [pvp.md](pvp.md)                                                                         |
| 아이템 graphic id, hue | [item-list.txt](item-list.txt). 상점 가격은 `script/loot/stock-vendor.razor` 상단이 정본 |
| 주문 데미지 메모       | [hotkeys.md](hotkeys.md) 6절                                                             |

없으면 위키를 읽고 해당 문서에 더한다. 더할 때:

- 인용문은 위키 또는 공식 패치노트 원문 그대로 `>` 로 적고, 해석은 인용문 아래에 따로 적는다.
- 인게임에서 확인된 것은 "인게임 확인됨" 과 날짜를, 확인되지 않은 것은 "확인되지 않았다" 로 남긴다.

## 2. 스크립트 고치기

1. **대상 스크립트를 끝까지 읽는다.** 메인 루프 하나에 타이머·타겟 캐시·후속 캐스팅이 얽혀 있어 한 분기만 고치면 다른 분기가 깨진다.
2. [razor.md](razor.md) 3절 확인된 함정 표를 본다. 새 패턴은 4절 선례에서 먼저 찾는다.
3. 요청 범위만 구현한다. 저장소에 근거 없는 패턴은 추가하지 않는다.
4. 고친 뒤 `util/check.sh <파일>` 로 `if/endif`, `while/endwhile`, `for/endfor` 짝과 미선언 변수를 확인한다.
5. 새 전투 루프를 만들면 [script/README.md](../script/README.md) 의 전투 루프 표에 한 줄 더한다.

## 3. 변경 보고

변경을 보고할 때 반드시 넣는다.

- 추가·변경된 변수와 타이머.
- 인게임 확인 절차: 어떤 상황에서 어떤 `overhead` 가 떠야 하고, 어떤 상황이면 실패인지.
- 4절의 반영 방법 (리로드로 되는지, 재시작이 필요한지)과 종료 후 `git status` 확인.

## 4. 게임에 반영하고 확인하기

### 4.1 스크립트 캐시와 리로드

Razor 는 스크립트 본문을 메모리에 캐시한다. 파일을 고친 뒤에는 Scripts 탭을 다시 열거나 우클릭 → Reload all scripts 를 해야 반영된다.

**`Reload all scripts` 는 핫키에 바인딩된 스크립트를 갱신하지 못한다.** 리로드는 기존 객체를 교체하지 않고 **새 객체를 목록에 덧붙인다.**
프로필에는 바인딩이 객체가 아니라 이름 (`Play Script: hotkey\bard-buff`)으로 저장돼 있어서, 키를 누르면 같은 이름 중 **맨 앞의 옛 객체**가 잡힌다.

| 어떻게 돌리나          | 리로드 뒤에 도는 본문 | 확인하려면                                          |
|------------------------|-----------------------|-----------------------------------------------------|
| Scripts 탭의 Play 버튼 | 새 본문               | 리로드만으로 충분하다. 반복 테스트는 이쪽으로       |
| 핫키                   | **옛 본문**           | **클라이언트를 껐다 켠다.** 리로드로는 절대 안 된다 |

리로드할 때마다 Hotkeys 목록에 `Play Script: ... (not assigned)` 가 한 줄씩 쌓인다 (메모리에만, 파일엔 안 남는다).

**파일을 고쳤는데도 스크립트 에러가 같은 줄번호를 계속 가리키면 캐시를 의심한다.** 줄을 지웠으면 그 아래 줄번호가
같이 움직여야 하는데 안 움직인다는 뜻이다. Reload all scripts 로 안 풀리면 클라이언트를 완전히 껐다 켠다.

### 4.2 캐시가 파일을 되돌린다

- 캐시가 옛 본문을 들고 있는 상태로 Razor 를 끄면 그 본문을 파일에 다시 쓴다. 외부 에디터로 고친 내용이 되돌아갈 수 있으니
  **종료 후 `git status` 로 확인한다.**
- 리로드를 반복하면 **옛 본문을 든 객체가 계속 쌓이므로 이 위험이 같이 커진다.** 이것도 재시작이 답이다.
- 외부 에디터로 스크립트를 고치는 프로필은 Razor 설정 `AutoSaveScript` 를 꺼 둔다.
- Razor 편집기에 직접 붙여넣으면 기존 객체의 본문이 바뀌므로 핫키도 새 본문을 쓴다. 다만 그 순간부터 **Razor 가 그 파일의 주인**이 되니, 외부 에디터 편집과 섞지 않는다.

검증 절차에는 4.1 의 반영 방법과 이 절의 `git status` 확인을 명시한다.

### 4.3 config 는 종료할 때 덮어쓴다

**`config/` 아래 파일은 종료 시 클라이언트가 통째로 덮어쓴다.** Razor 프로필 xml 뿐 아니라
ClassicUO 의 `cooldowns.xml`, `macros.xml` 등 전부 해당된다. **게임을 끈 상태에서만 수정한다.**
켜둔 채로 고치면 종료할 때 조용히 사라진다. 실제로 한 번 날아갔다.

## 5. 문서 고치기

### 5.1 한 사실은 한 곳에

같은 내용을 두 문서에 쓰지 않는다. 한 곳을 정본으로 두고 다른 곳은 절 번호로 링크한다.
두 곳에 쓰면 한쪽만 고쳐지고, 어느 쪽이 맞는지 모르게 된다 (overheads.md 의 옛 hue 표가 그렇게 틀렸다).

| 무엇                                   | 정본                                             |
|----------------------------------------|--------------------------------------------------|
| 파일 위치, 이름, 스크립트 모양, 변수   | [conventions.md](conventions.md)                 |
| 문법, 함정, 명령문 비용, PvP 명령 제약 | [razor.md](razor.md)                             |
| 작업 순서, 반영·검증, 문서 규칙, 커밋  | 이 문서                                          |
| 머리 위 메시지, 쿨다운 바, hue         | [overheads.md](overheads.md)                     |
| 템플릿과 무관한 PvP 규칙과 숫자        | [pvp.md](pvp.md)                                 |
| Bard Necro 의 메커니즘, 설계, 판단     | [bard-necro-handbook.md](bard-necro-handbook.md) |
| 키 배치                                | [hotkeys.md](hotkeys.md)                         |
| 전투 루프와 템플릿 대응                | [script/README.md](../script/README.md)          |

템플릿 문서 (bard-necro-handbook 같은)에는 **그 템플릿이 내린 판단**만 둔다. 서버 규칙이나 문법처럼
다른 템플릿에서도 쓰는 내용이 생기면 공통 문서로 옮기고 링크를 남긴다.

### 5.2 문서 모양

- 맨 위: `#` 제목, 이 문서가 답하는 것 한두 줄, 여기 없는 것은 어디 있는지 링크.
- 그다음 `## 목차`. 절은 `## 1.` `### 1.1` 처럼 번호를 붙이고, 목차는 절과 같은 순서·같은 이름으로 유지한다.
  절을 넣거나 빼면 목차와 번호를 같이 고치고, 그 번호를 인용한 곳 (`grep -rn '5.8절' library/`)도 고친다.
- 목차의 앵커는 GitHub 규칙이라 제목에 백틱·따옴표·괄호를 넣지 않는다. 앵커가 깨진다.
- 다른 문서는 상대 경로 링크로, 절은 "파일 N절" 로 가리킨다.
- 표는 파이프를 맞춰 정렬한다.
- 한 줄은 200자까지 (`.editorconfig` 의 `max_line_length`). 문장 중간에서 끊지 말고, 넘으면 문장 경계에서 줄을 바꾼다.

### 5.3 새 문서

- `library/` 에 kebab-case 로 만든다. 템플릿 전용이면 `<템플릿>-handbook.md`.
- 만들면 [AGENTS.md](../AGENTS.md) 의 문서 지도와 루트 [README.md](../README.md) 의 `library/` 줄에 더한다.
- 5.1 의 정본 표에 무엇의 정본인지 한 줄 더한다.

### 5.4 언어와 번역본

- 문서와 답변은 한국어, 스크립트 안 주석은 영어.
- 사람이 처음 보는 README 는 영어가 원본이다. 번역본은 `language/` 에 `<무엇>.<언어>.md` 로 둔다
  (`language/README.ko.md` 는 루트 README, `language/config.ko.md` 는 `config/README.md`).
- 원본 맨 위에 번역본 링크, 번역본 맨 위에 원본 링크를 둔다. 원본을 고치면 번역본도 같은 커밋에서 고친다.

## 6. 커밋

- 사용자가 커밋하라고 할 때만 커밋한다. push 는 별도 요청이 있을 때만.
- 제목 한 줄, 영어, 마침표 없음. 본문·트레일러·`Co-Authored-By` 는 넣지 않는다.
- Conventional Commits 접두 (`feat:`, `fix:`)를 쓰지 않는다. 동사로 시작하는 평서문.

| 좋음                                 | 나쁨            | 왜                       |
|--------------------------------------|-----------------|--------------------------|
| `Regroup scripts by activity`        | `feat: regroup` | 접두를 쓰지 않는다       |
| `Add eval rotation to bard-necro`    | `update`        | 무엇을 바꿨는지 없다     |
| `Fix stuck target loop in bard-mace` | `스크립트 수정` | 영어, 대상과 동작이 없다 |

- 한 커밋에 한 가지 변경. 스크립트 수정과 문서 수정이 독립적이면 나눈다.
