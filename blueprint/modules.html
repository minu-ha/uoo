Modules

루프를 블록 단위 모듈로 한 벌만 두고, 루프마다 레시피로 조립하는 방식이다. 모듈과 레시피의 형식, 조립 규칙, core 모듈의 스위치, 옮긴 기록을 다룬다. 스크립트 모양과 이름 규칙은 conventions.html, Razor 문법의 함정은 razor.html에 있다.

01 왜 모듈인가

같은 블록이 루프마다 복사돼 있었다. 2026-10-09 스탯 포션 판정을 바꾸는 데 스크립트 8개를 고쳤고, 그중 skinning-enhanced에는 다른 루프에서 이미 고친 elseif 사슬 버그가 그대로 남아 있었다. 회복·포션·버프·시약 블록은 모듈로 한 벌만 두고, 루프마다의 레시피에는 어떤 블록을 어떤 순서로 쓰는지와 그 루프의 설정 전부를 적는다.

조립은 저장소에서 한다. Razor는 한 번에 스크립트 하나만 돌리고, 다른 스크립트를 켜면 지금 것이 멈춘다. 함수 호출이나 include도 없다. 게임 안에서 모듈 스크립트를 차례로 켜는 방식은 쓰지 않는다.

  • 패스마다 스크립트를 몇 번씩 새로 켜야 하는데, 그 비용은 재 본 적이 없다. 회복이 늦어질 수 있다.
  • script가 돌아오는지 넘어가는지 확인되지 않았다.
  • Esc는 지금 모듈만 멈추고, 한 모듈의 오류가 사슬 전체를 조용히 끊는다.

조립기가 만든 결과물은 지금까지와 같은 단일 .razor 파일이다. 게임과 핫키는 달라지지 않는다.

02 폴더와 역할

설정 (config__)은 레시피에만, 동작은 모듈에만 둔다. 루프 하나의 설정을 고치려면 그 레시피 하나만 열면 된다.

자리 무엇 가진 것
recipe/<루프>-recipe.razor루프 하나가 무엇인지헤더, 도는 순서대로 적은 블록 목록, 그 루프의 설정 전부, 그 루프만의 준비 (시작 메시지, 루트 파우치, 복귀 등록)
module/core/여러 루프가 같이 쓰는 블록시작 줄, PvP 정지, 시약, 마비, 큐어, 힐, 붕대, 가벼운 Heal, Refresh, 스탯 포션, 자기 버프, 패스 끝. 그리고 블록이 아닌 공용 모듈: 출력 스위치 (core/output), 회복 스위치 (core/switches), 대기 값 (core/wait), 경고 간격 (core/message)
module/combat/전투 루프만 쓰는 블록pvp의 무기 슬롯
module/gather/채집 루프만 쓰는 블록전투 대상, 도끼, 골드, 소드·패리 codex, 무기 능력, 칼질, 음식, 가죽, housekeeping, Tracking 설정, 자동 리콜, 벌목
util/build-scripts.py조립기레시피를 읽어 결과물을 만들고, 빠진 설정과 안 쓰는 설정을 막는다
script/combat/pvp.razor, script/gather/*.razor결과물직접 고치지 않는다

레시피 이름에 -recipe를 붙이는 것은 편집기 탭에서 결과물과 헷갈리지 않게 하려는 것이고, .razor는 하이라이팅을 받으려는 것이다. module/과 recipe/는 저장소 루트에 둔다. script/는 Razor Scripts 폴더에 링크되므로, 그 안에 두면 조각 파일이 스크립트 목록에 떠서 혼자 실행될 수 있다.

03 레시피

레시피는 위에서 아래로 읽으면 루프가 보이게 쓴다. #@로 시작하는 줄은 조립기가 읽는 지시이고, Razor에서는 주석이다.

부분 무엇
첫 지시 앞의 # 주석레시피를 고치는 사람을 위한 메모. 결과물에 나가지 않는다
#@ output script/<폴더>/<루프>.razor결과물 경로
#@ header결과물 맨 위 주석 (conventions.html 02.C절). 핫키 줄은 조립기가 붙인다
#@ blocks한 줄에 #@ use <모듈> 설명 하나. 루프 안에서 도는 순서다. # 주석은 읽는 사람을 위한 구분이다
#@ config블록들이 읽는 설정 전부. 묶음마다 # ---- core/heal ----처럼 그 설정을 읽는 모듈을 적는다. 그 루프만 기본과 다른 값이면 위에 # This loop: 이유를 쓴다. 결과물의 CONFIG가 된다
#@ state, #@ setup그 루프만의 상태와 루프 전 준비 (없어도 된다)
 
#@ blocks
# Before the loop.
#@ use core/start              clears the client queues
#@ use core/pvp-stop           stops inside structured PvP, here and at the top of every pass
# Every pass, in this order.
#@ use core/heal               heal potion, else Greater Heal at the emergency line
#@ use core/reagents           reagent flags, read after Tracking so it cannot consume a report

#@ config
# ---- core/heal -----------------------------------------------------------------
@setvar! config__heal_hits 35
# This loop: Bandages handle ordinary damage, so Greater Heal waits for 45.
@setvar! config__emergency_hits 45

블록 순서는 루프 안 순서이자 선언 순서다. insysmsg로 오래된 줄까지 소비하는 블록은 위치가 중요하다. lumberjack-enhanced는 Tracking 감지 줄을 먼저 읽도록 시약을 자동 리콜 뒤에, skinning-enhanced는 칼질 응답 뒤에 둔다.

04 모듈

module/<자리>/<이름>.razor 하나가 블록 하나다. 이름은 core/heal처럼 자리와 파일 이름으로 부른다. Razor 파일은 섹션 순서가 정해져 있어서, 모듈은 부분별 조각을 표시해 두고 조립기가 결과물의 제자리에 모은다.

줄 뜻
첫 지시 앞의 # 주석모듈이 하는 일. 결과물에 나가지 않는다
#@ needs <모듈> …이 모듈이 읽는 값을 선언하는 모듈. 블록인 것은 레시피에 있어야 하고, 블록이 아닌 공용 모듈 (core/wait 등)은 조립기가 알아서 넣는다
#@ after <모듈> …둘 다 있을 때 패스에서 이 모듈보다 앞서야 하는 모듈
#@ hotkeys A, B이 모듈이 부르는 Razor 핫키. 결과물 헤더의 Hotkeys: 줄에 모인다
#@ settings이 모듈이 읽는 설정의 설명서. 주석과 제안 값이 든 @setvar! config__ 줄이다. 결과물에 나가지 않고, --settings가 이것을 레시피용으로 뽑아 준다
#@ prelude헤더 바로 뒤. 시작 4줄, PvP 정지
#@ wait / #@ stateWAIT AND COOLDOWN, STATE에 들어갈 내부 값 (wait__, cooldown__, var__)
#@ timer / #@ readyTIMER의 createtimer 묶음과 그 뒤의 첫 settimer (conventions.html 04절)
#@ setup루프 앞에서 한 번 하는 준비. 배너는 모듈이 직접 쓴다
#@ loopwhile not dead 안의 블록. 배너와 주석까지 그대로 나간다

모듈은 config__에 값을 넣지 않는다. 내부 값 (wait__, cooldown__)은 모듈이 정하고 모든 루프가 같은 값을 쓴다. 루프마다 달라야 하는 값이 생기면 config__ 설정으로 바꿔 레시피로 올린다.

05 조립 규칙

  1. 헤더: 레시피 헤더 → 블록들이 선언한 핫키를 모은 Hotkeys: 줄 → "Generated from recipe/… by util/build-scripts.py" 줄.
  2. prelude → CONFIG (레시피의 #@ config 그대로) → WAIT AND COOLDOWN → TIMER (timer 조각, 빈 줄, ready 조각) → STATE (레시피 먼저) → setup (레시피 먼저) → MAIN LOOP (while not dead, 블록 순서대로 loop 조각, endwhile). 조각 사이는 빈 줄 하나, ready만 빈 줄 없이 붙인다.
  3. 조립기는 아래에서 멈춘다.
    • 블록이 읽는 설정이 레시피 #@ config에 없다. 오류에 설정 이름과 읽는 모듈이 나온다.
    • 레시피 #@ config에 아무 블록도 읽지 않는 설정이 있다.
    • 모듈 코드가 읽는 config__를 그 모듈이나 그 모듈의 needs가 #@ settings에 설명하지 않았다.
    • 모듈이 config__에 값을 넣는다.
    • 두 곳이 같은 변수나 타이머를 선언한다.
    • 블록인 needs가 레시피에 없거나, after 순서가 틀렸다.
  4. 줄 끝은 CRLF로 쓴다 (.gitattributes). 바뀐 결과물만 다시 쓴다.
  5. util/check.sh를 인자 없이 돌리면 끝에 util/build-scripts.py --check도 돈다. 누가 결과물을 직접 고쳤으면 여기서 잡힌다.

06 core 모듈과 스위치

core 블록은 pvp v6~v8에서 다듬은 모양을 따른다. 각 블록이 지금 상태를 읽고 그 자리에서 행동하며, 다음 블록에 결정을 넘기지 않는다. 재시도 타이머 대신 행동 큐 (queued), bandaging, findbuff, 포션 라벨과 heal pot 바가 반복을 막는다. 예외는 Strength·Agility 포션의 5초 간격이다 (pvp.html 09.D절). 루프마다 다른 점은 아래 설정으로 고른다.

config__walk_guardcore/switches11이면 우리 시전이 walk 바가 도는 동안 기다린다. pvp는 0이다. 싸움 중에는 기다릴 더 나은 때가 없다
config__warmode_is_manualcore/switches01이면 워모드가 플레이어의 수동 조작 창이라 우리 시전이 선다. lumberjack-enhanced만 1이다

07 작업 순서

  1. 루프 하나의 값을 바꾸려면 그 레시피의 #@ config만 고친다. 기본과 다르게 둔 이유는 # This loop:로 남긴다.
  2. 블록의 동작을 바꾸려면 그 모듈을 고친다. 그 모듈을 쓰는 루프가 모두 바뀐다.
  3. python3 util/build-scripts.py로 다시 만들고 util/check.sh를 돌린다.
  4. 결과물을 게임에서 확인할 때는 지금처럼 Reload all scripts 뒤 Play한다 (workflow.html 04절).
  5. 결과물, 모듈, 레시피를 한 커밋에 넣는다.
  • 새 루프: 레시피에 #@ output, #@ header, #@ blocks를 쓰고 python3 util/build-scripts.py --settings recipe/<루프>-recipe.razor를 돌린다. 필요한 설정 묶음이 주석과 제안 값까지 나오니 #@ config 아래에 붙이고 값을 고친다. 모듈을 열어 맞출 필요가 없다.
  • 블록에 설정을 새로 더하면 모듈의 #@ settings에 설명을 쓰고, 그 모듈을 쓰는 레시피마다 값을 넣는다. 빠뜨리면 조립기가 멈춘다.
  • 두 루프가 같은 블록을 따로 들고 있게 되면 core로 올린다. 다른 점은 설정으로 남긴다.
  • Razor 편집기에서 결과물을 저장해 버렸으면 --check가 잡는다. 바뀐 줄을 모듈이나 레시피로 옮기고 다시 만든다.

08 2026-10-10 옮긴 기록

pvp (v9)는 동작이 같다. 처음에는 블록을 그대로 잘라 옮겨 루프가 글자까지 같았다. core 스위치를 넣은 뒤에도 pvp 설정값 (walk_guard 0, warmode_is_manual 0, buff_when_poisoned 1, heal_skill_min 0, buff_max_loss 35 = emergency_hits)을 넣어 항상 참인 감싸기 조건을 걷어 내면 원래 루프와 문장이 같았다.

skinning-enhanced (v11)와 lumberjack-enhanced (v17)는 회복·포션·버프·시약이 core로 바뀌었다. 두 루프만의 블록 (전투 대상, 도끼, 골드, codex, 무기 능력, 칼질, 가죽, Tracking 설정, 자동 리콜, 벌목)은 경고 타이머 이름을 timer__message로 바꾼 것 말고는 글자까지 같다. 손실선·마나·Refresh 기준 같은 값은 레시피의 설정으로 그대로 두었다. 바뀐 동작은 아래와 같다.

무엇 전 지금
회복 주문 선택위에서 var__heal_spell을 고르고 아래 SELF AGENT가 시전큐어, 힐, 가벼운 Heal 블록이 각자 지금 상태를 읽고 바로 시전
