Lumberjacking을 유지하면서 도끼·붕대·마법으로 필드에서 반격하는 캐릭터의 선택과 교전 설계.
서버 규칙의 정본은 [pvp.md](pvp.md), 미확인 메커니즘과 실험 절차는 [open-items.md](open-items.md#08) 08절이다.

## <a id="00"></a>00 한눈에

**벌목 120을 유지하는 근접 중심 하이브리드**다. 순수 결투 캐릭터의 최적해라고 단정하지 않는다.
2026-10-01 대화에서 근접·붕대 중심으로 갱신했다. 아래 수치는 공식 기반 계산이고 전투 시나리오는 아직 실전 검증 전이다.

- 기본안은 720 스킬, STR / DEX / INT = **100 / 80 / 45**. 도끼 압박과 붕대를 우선한다.
- Great Axe로 한 방, Norse Axe로 붙어서 압박, Hatchet은 벌목과 중간 속도용이다.
- 상대도 자동 파우치·붕대·포션을 쓴다. Paralyze 동안 멈춰 기다려 주는 상대를 가정하지 않는다.
- TK는 자기 방어와 공격 부착 중 선택한다. **반사 TK를 공짜 자기 방어로 계산하지 않는다.**
- Explosion → EB 자동 콤보는 제외한다. 마법은 짧은 견제·회복·이동, TK → 폭발 포션은 적용 확인이 가능한 경우에 한한다.
- 채집용 `lumberjack-enhanced`와 공통 PvP 자기관리 `pvp`를 쓴다. 각각 08절과 09절에 적었다.
  별도 핫키로 수동 전환하며, 두 파일 모두 인게임 확인 전이다.

## <a id="01"></a>01 스킬 720

| 스킬 | 값 | 이 템플릿에서 맡는 일 |
| --- | --- | --- |
| Lumberjacking | 120 | 채집 목적을 유지하고 도끼의 PvP 보조 피해를 얻는다 |
| Swordsmanship | 100 | 도끼의 명중·무장 중 근접 방어. Lumberjacking으로 대체할 수 없다 |
| Tactics | 100 | 근접 기본 피해의 페널티를 없앤다 |
| Magery | 80 | 회복·해독·이동·짧은 견제·TK. Explosion / EB는 자동 루프에서 제외 |
| Tracking | 80 | 적 탐지, 보조 피해, Hamstring 자격의 한 자리 |
| Resisting Spells | 80 | 주문 피해 방어. PvP 시전 인터럽트 면역은 아니다 |
| Anatomy | 80 | Hamstring 자격의 다른 자리, 근접 기본 피해·붕대 보조 |
| Healing | 80 | 공격 마나를 남겨 주는 붕대 회복 |
| 합계 | 720 | Eval / Meditation / Wrestling / Alchemy 없음 |

Hamstring은 Swordsmanship으로 공격하고 Anatomy + Tracking으로 보조 조건을 채운다.
**Swordsmanship + Tracking만 있는 것으로는 부족하다.** 조건 원문은 [pvp.md](pvp.md#03) 03절.

Lumberjacking 120의 +12%와 Tracking 80의 +8%로 도끼의 근접 보조 상한을 채운다.
Tracking의 주문 보조는 +8%지만 Eval을 대신하지 않는다. Tactics와 Anatomy도 그 상한 밖이다
([pvp.md](pvp.md#09.A) 09.A절).

무기를 들면 Swordsmanship으로 싸우지만, 시전으로 손을 비우면 Wrestling 없는 약점이 드러난다.
상대 무기 스킬 100 대 내 맨손 Wrestling 0의 기본 명중은 100%다. 가까이서 긴 시전을 버티는 운영은 피한다
([pvp.md](pvp.md#02.E) 02.E절).

### <a id="01.A"></a>01.A 마지막 20점의 선택

Lumberjacking 120, Swordsmanship 100, 나머지 여섯 스킬 80이면 700이다. 다음은 남은 20점을 어디에 넣을지의 비교다.

| 100으로 올릴 스킬 | 얻는 것 | 선택 기준 |
| --- | --- | --- |
| Tactics — 기본안 | 기본 무기 피해의 -10% 보정 제거 | 도끼로 붙어서 마무리할 계획에 우선 |
| Healing | 슬립 전 붕대 평균 46.4 → 58 | 마나를 힐에 너무 많이 쓰거나 지속 교환에서 밀리면 비교 |
| Resisting Spells | 주문 피해 방어 강화 | 메이지 폭딜에 회복하기도 전에 무너지면 비교 |
| Tracking | 탐지 거리·성공률, 주문 보조 +8% → +10% | 조기 발견이 최우선일 때. 도끼 보조 피해는 이미 상한이다 |
| Anatomy | 근접 기본 피해 +16% → +20%, 붕대 평균 46.4 → 48 | 회복량만 보면 Healing 증량보다 작다 |

계산 근거는 [pvp.md](pvp.md#09.A) 09.A·09.C절, 방어는 [08절](pvp.md#08), 탐지는 [10절](pvp.md#10)이다.

### <a id="01.B"></a>01.B Magery 80과 Eval·Meditation을 뺀 비용

Magery 80은 유틸리티와 Greater Heal을 위해 유지한다. 자동 Explosion / EB를 빼도 Magery 60으로 낮추는 안까지 채택한 것은 아니다.
Earth Elemental 스크롤의 성공률과 필요한 마나는 별개다. **기본 최대 마나 45로는 50마나 소환을 할 수 없다.**
버프로 실제 마나 50 이상을 확보했는지 확인해야 하며, 소환 직후는 교전 준비가 안 된 상태다
([pvp.md](pvp.md#05.B) 05.B절, [06절](pvp.md#06)).

Magery 100은 단지 7·8서클 때문에 찍는 것이 아니다. 피해와 Greater Heal도 강해진다.
Magery 80의 GH는 기본 32\~40 회복이다. 60으로 줄이는 선택은 회복량·시전 신뢰도를 다시 비교해야 한다.

Eval 없는 주문은 주력 메이지의 공격과 같지 않고, Meditation 없는 마나는 긴 주문 교환을 버티기 어렵다.
현재안은 둘 중 무엇을 80 넣을지 고르는 안이 아니라 **Anatomy + Healing을 함께 유지하는 안**이다.

예전의 Wrestling 80 + Eval 80 또는 Meditation 80 안으로 돌아가려면 Anatomy + Healing을 빼는 식의 재설계가 필요하다.
그 경우 Hamstring은 Tracking + Wrestling로 충족하지만 붕대를 잃는다. 주문전 위주로 바꾸고 싶을 때 별도로 비교한다.

## <a id="02"></a>02 스탯 225와 회복

STR 100을 고정하고 DEX와 INT를 나눈다. 아래는 Greater Agility +20만 반영한 값이다.
Greater Strength 사용 시 최대 HP는 120으로 계산한다. Bless의 정수·중첩 처리는 제외한다
([pvp.md](pvp.md#09.D) 09.D절).

| STR / DEX / INT | 포션 후 DEX | 자기 붕대 | 판단 |
| --- | --- | --- | --- |
| 100 / 25 / 100 | 45 | 약 13.67초 | 마나는 넉넉하지만 원하는 붕대 11\~12초보다 느리다 |
| 100 / 50 / 75 | 70 | 12초 | 이전안. 긴 공격 주문까지 쓸 때의 비교용 |
| 100 / 60 / 65 | 80 | 약 11.33초 | 근접과 회복을 조금 더 중시 |
| 100 / 65 / 60 | 85 | 11초 | 붕대 목표를 확실히 당기되 마나 여유 감소 |
| **100 / 80 / 45** | 100 | **10초** | 현재 기본안. 도끼·붕대 중심, 마나는 유틸리티에 보존 |

[pvp.md](pvp.md#09.C) 09.C절 공식에 대입한 이론값이다. 자동 붕대는 재사용 실수를 줄이지 완료 시간을 줄이지는 않는다.
DEX를 더 올려도 서버의 계산 상한을 넘는 부분은 붕대·PvP 공속에 추가 이득을 주지 않는다.

출발안에서 실제로 부족한 것을 기록한다. 마나가 먼저 고갈되면 공격 주문 소비를 줄이고,
붕대 완료 전 압박에 밀리면 Healing 증량의 비용을 비교한다. 포션 만료·Curse·독·슬립이 섞인 결과도 분리한다.

Bless는 Magery 80에서 공식상 INT +8.8이다. **45 + 11 = 56으로 계산하지 않는다.**
정수 처리와 현재 마나 증가 여부는 미확인이다. 시전에는 9마나가 들므로 발견 직후 Bless만으로 즉시 마나 여유가 늘었다고 판단하지 않는다.
포션과 STR·DEX 중첩도 실측 전에는 합산하지 않는다 ([pvp.md](pvp.md#09.D) 09.D절).

### <a id="02.A"></a>02.A 장비 출발안

기본 방어구는 Leather로 잡는다. Meditation 0에서도 자연 재생은 있지만, 가죽은 추가 재생 보너스가 아니라 방어구 재생 페널티가 없는 선택이다.
Studded의 물리 방어는 무기를 섞는 메이지나 근접 상대에게 가치가 있으므로 항상 무의미하다고 단정하지 않는다.

Great Axe·Norse Axe를 전투용으로, Hatchet을 벌목 겸 예비용으로 준비한다. 무기 품질·마법 옵션과 방패 운용은 아직 확정하지 않았다.
장비를 바꾼 실측과 아래 일반 무기 계산을 섞지 않는다. 상세 재생 조건은 [pvp.md](pvp.md#05.D) 05.D절.

## <a id="03"></a>03 도끼와 스윙

[Swordsmanship 무기표](https://wiki.uooutlands.com/Swordsmanship)에서 목적별 도끼를 고른다.
Katana·Halberd가 같은 스킬을 쓴다는 이유로 Lumberjacking 보너스를 받는 것은 아니다
([pvp.md](pvp.md#09.A) 09.A절).

| 무기 | 역할 | Speed | 기본 피해 |
| --- | --- | --- | --- |
| Great Axe — 2H Burst | 접촉 순간 한 방과 Hamstring 시도 | 25 | 21\~46 |
| Hatchet — 2H Medium | 벌목 도구 겸 중간 속도의 지속전 | 38 | 17\~32 |
| Norse Axe — 1H Light | 붙어 있는 동안 더 자주 명중·인터럽트를 시도 | 48 | 13\~23 |

위 값은 무기표의 Speed·MinDmg·MaxDmg이다. 상대에게 실제 뜨는 피해에는 스킬·방어구 등 다른 계산이 들어간다.

| 현재 스태미나 | Great Axe | Hatchet | Norse Axe |
| --- | --- | --- | --- |
| 45 | 4.14초 | 2.72초 | 2.16초 |
| 70 — 이전안 | 3.53초 | 2.32초 | 1.84초 |
| 80 | 3.33초 | 2.19초 | 1.74초 |
| 100 — 현재안의 만스태미나 | 3초 | 1.97초 | 1.5625초 |

[pvp.md](pvp.md#09.B) 09.B절 공식으로 계산했다. 피해로 스태미나가 내려가면 포션 후 최대 DEX만으로 공속을 예상할 수 없다.

예를 들어 스태미나 100에서 Great Axe를 t=0에 휘두르고 Norse Axe를 t=1.5625에 휘두르면,
다음 Great Axe는 t=4.5625부터다. 원래 Great Axe 간격인 t=3에 공짜로 다시 치는 것은 아니다.

따라서 "큰 무기 쿨이면 무조건 작은 무기"가 아니다. 곧 상대가 붙어서 큰 한 방을 줄 기회가 생길지,
지금 빠른 스윙으로 상대 회복 시전을 견제하는 게 나을지 고른다. 명중 자체는 보장되지 않는다.

## <a id="04"></a>04 마나 예산과 시작 조건

[pvp.md](pvp.md#05.B) 05.B절의 기본 마나를 합산한 값이다. 자연 회복·실패·추가 시전은 제외했다.
INT 45는 기본 최대 마나다. 실제 현재 마나·재생·회복 예약을 보고 행동한다.

| 행동 묶음 | 마나 | 판단 |
| --- | --- | --- |
| TK + 폭발 포션 | 9 | 공격 TK 적용을 확인할 수 있을 때만 포션 점화. 포션 자체의 마나는 없음 |
| GH + Teleport | 20 | 공격보다 먼저 남길 초기 예약량. 생존 보장치는 아님 |
| TK + TP + GH + MA 두 번 | 37 | 30초 동안 썼다면 이상적 자연 재생 15를 빼 순소모 22 |
| TK + Explosion + EB | 49 | 기본 최대 마나 45를 넘고 회복 여유도 없다. 자동 루프에서 제외 |

설계상 최소 여유로 GH + Teleport 몫을 별도로 확보한다. 이것은 생존 보장치가 아니라 한 번의 회복·이동 예산이다.
추가 해독·견제·실패 비용이 필요하면 긴 콤보를 포기한다. 자기 TK를 미리 걸었어도 회복하지 않은 마나는 이미 소비한 것이다.

Rope는 기본 추격 수단으로 자동 사용하지 않는다. 마나 부족 등 정말 필요한 상황의 수동 선택으로 남기되,
이후 Teleport까지 공유 쿨에 묶이는 비용을 보여 줘야 한다 ([pvp.md](pvp.md#05.C) 05.C절).

가죽·Meditation 0의 자연 재생은 초당 0.5다. 위 30초 예시에서 45로 시작하면 약 23이 남지만,
만마나에서 버린 재생·시전 시점·추가 해독·실패는 제외한 예산이다. 실제 잔량을 보장하지 않는다.

TK를 30초마다, TP를 15초마다 계속 쓰면 둘만으로 초당 0.9마나를 쓴다. 재생보다 빠르므로 쿨마다 자동 사용하지 않는다.
붕대·포션이 기본 회복이어도 위험할 때 GH를 끝까지 미루지 않는다. 자연 재생 조건은 [pvp.md](pvp.md#05.D) 05.D절.

## <a id="05"></a>05 상대도 스크립트를 쓰는 전투

05.A\~05.C는 TK·폭발 포션을 쓰는 Alchemy + Inscription 메이지를 가정한 교전 판단이다.
사용자가 선택한 Inscription 없는 순수 Alchemy 메이지와의 조건부 계산은 05.D절에 별도로 적었다. 일반 교전 판단은
상대의 이동·회복·반사와 내 실패에 대응하는 의사결정이다. 이벤트별 명령 제한은 별도로 확인한다.

### <a id="05.A"></a>05.A 기본안 — 이동 중 접근, 접촉하면 도끼

1. **발견:** Tracking으로 발견하면 무게·퇴로·마나·포션 상태를 본다. 과적 채집 상태에서 쫓기 시작하지 않는다.
   먼저 반격 주문을 쓰면 도주 제한도 생긴다 ([pvp.md](pvp.md#01) 01절).
2. **TK 선택:** 전투 제어가 활성화된 동안만 수동 Tab의 Warmode ON은 공격 TK, OFF는 자기 TK의 의도로 읽는다.
   Warmode를 스크립트가 바꾸지 않는다. OFF인 평상시까지 자기 TK를 반복하지 않으며, 기존 시전자 공용 쿨을 우회하지 않는다.
   공격 TK → 포션 조건을 충족하면 05.B절을 먼저 처리한 뒤 아래 견제로 돌아온다.
3. **견제:** 사거리·LOS·예약 마나가 맞으면 MA 한 번을 쓴다. 낮은 반사 피해를 감수하는 선택이지 Reflect 소진 확인이 아니다.
   Inscription을 이유로 두 발을 강제하지 않고, 다음 행동으로 긴 공격 주문을 예약하지 않는다.
4. **접근:** 기본은 이동이다. 짧은 주문을 선택하면 시전에 필요한 동안 멈춘 뒤 다시 추격한다.
   상대가 멈춰 있어야만 견제하는 구조도, 이동하면서 끊김 없이 시전된다고 가정하는 구조도 아니다.
5. **접촉:** 실제 근접 사거리와 공유 스윙 준비를 확인해 Great Axe와 Hamstring을 시도한다.
   붙어 있는 동안 Norse Axe로 압박한다. 근접 스윙 사이에 새 공격 주문을 끼워 넣지 않는다.
6. **이탈:** 상대가 달아나면 따라붙되 거리·마나가 맞을 때만 MA 또는 Harm 한 번을 쓴다.
   시전 실패나 사거리 이탈 뒤 즉시 연속 재시전하지 않는다. 다시 붙으면 공유 스윙에 맞춰 도끼로 돌아온다.
7. **회복:** 붕대·포션을 기본으로 하되 위급하면 GH·해독·퇴로 확보가 공격보다 우선한다.
   상대도 포션을 먹으며 달릴 수 있으므로 내 포션을 맞고 반드시 GH를 시전하러 멈춘다고 가정하지 않는다.

Warmode는 공격 의도이지 상대 Reflect 상태가 아니다. Explosion / EB는 별도 수동 마무리 선택으로 남길 수 있지만,
현재 기본 루프와 마나 예산에는 넣지 않는다. 상대 시전 상태를 읽지 못한다면 견제이지 확정 인터럽트라고 표시하지 않는다.

| 거리 분기 초안 | 행동 |
| --- | --- |
| 실제 근접 사거리 | 도끼 우선. 화면상 1\~2타일 표시만으로 명중 가능을 확정하지 않음 |
| 근접 밖 \~4타일 | MA 또는 Harm 한 번, 이후 접근 재개 |
| 5\~6타일 | MA 우선. Harm은 원거리 피해 감소를 감안해 2서클 견제가 필요할 때만 검토 |
| 6타일 밖 | 접근 우선. 실측 후 시작 임계값 조정 |

6타일은 시험할 **시전 시작 임계값**이지 서버 최대 사거리가 아니다. 주문·포션의 대상 지정 거리와 LOS를 따로 검증한다.
MA 0.5초, Harm 0.75초 시전과 서클별 제한은 [pvp.md](pvp.md#05.A) 05.A·05.B절.

### <a id="05.B"></a>05.B 조건부 공격안 — 공격 TK 직후 포션

공격 TK를 선택하고 적에게 실제 적용한 경우에만 포션 부착을 기대한다. 자기 TK 방어와 동시에 확보했다고 가정하지 않는다.
포션 부착 안내는 자기 TK에도 뜨므로 대상 문맥 없이 성공으로 읽지 않는다. TK는 Reflect 제거 수단으로 쓰지 않는다
([pvp.md](pvp.md#04.C) 04.C절).

1. 공격 대상 A의 serial을 저장하고 공격 TK의 시도와 대상 변경을 관리한다. Last Target만을 전투 대상 저장소로 쓰지 않는다.
2. 공격 TK가 A에게 적용됐다고 신뢰할 수 있고 투척 거리·LOS가 맞으면 바로 포션을 던진다. TK와 포션 사이에 MA를 끼우지 않는다.
3. 현재 관찰 신호만으로는 그 신뢰 조건을 항상 충족할 수 없다. 응답 대기 중 적 TK가 들어온 경우는 미확인으로 남기고 점화하지 않는다.
4. 이미 확인된 공격 TK 뒤에 적 TK를 맞은 것과, 성공 판정 자체가 모호한 경우는 다르다. `teleki, me`만으로 전자를 무효화하지 않는다.
5. 실제 부착 확인 뒤 접근해 도끼와 Hamstring을 노린다. 투척 성공·부착 성공·명중 피해는 서로 다른 상태다.

Hamstring은 침묵이나 기절이 아니다. 상대는 그동안에도 회복·공격 주문과 포션을 사용할 수 있다.
Paralyze도 자동 파우치 상대를 긴 콤보 동안 고정하는 도구로 계산하지 않는다.

상대가 내게 포션을 붙였을 때 투척자와 폭발 범위 안에 함께 들어가 Splashback을 노릴 수는 있지만,
진입하면 더 큰 근접·주문 피해를 받는 상황인지 먼저 본다 ([pvp.md](pvp.md#04.A) 04.A절).

**구현 차단 조건:** 시도 뒤 새 안내 + 같은 대상 + target 바만으로는 내 공격 TK 성공을 입증하지 못한다.
허위 성공을 허용하지 않으려면 독립적인 확인 수단을 검증하기 전 자동 점화를 보류해야 한다
([pvp.md](pvp.md#04.D) 04.D절). 이 문서는 완전 자동 TK → 포션이 안전하게 해결됐다고 선언하지 않는다.

### <a id="05.C"></a>05.C 길어진 교전과 철수

붙지 못한 채 주문만 교환하면 이 구성은 Eval·Meditation을 갖춘 메이지보다 불리한 자원 구조다.
상대가 회복을 마쳤는데 내 마나·스태미나만 줄어들면 같은 오프너를 반복하지 않는다.

- 원거리 견제는 MA·Harm을 기본으로 하되 고정 회전시키지 않는다. 거리·마나·서클별 제한을 보고 선택한다.
- 붕대는 미리 돌아가게 하되, 완료 전 버틸 수 없으면 포션·GH·시야 차단을 쓴다. 자동 사용은 판단 비용을 줄일 뿐 피해를 없애지 않는다.
- 추격용 Teleport를 쓴 직후에는 탈출용으로 바로 다시 쓸 수 없다. 포션이나 가방의 자원도 출발 시점에 검사한다.
- 철수는 이동·시야 차단을 기본으로 생각하고, 공격 후 즉시 Recall할 수 있다고 가정하지 않는다.

### <a id="05.D"></a>05.D 순수 Alchemy 메이지와 30초·60초 모형

2026-10-05 사용자가 선택한 비교다. **실제 필드 승률은 알 수 없다.**
아래는 정해진 행동을 반복하는 두 캐릭터가 제한 시간 안에 상대를 처치하는 비율이다.

**던전에서 처음 마주친 뒤 10초 안에 죽는 상황의 생존 판단에는 사용할 수 없다.**

#### 실험 결과

근접 여부는 평균 2초의 접촉 구간과 비접촉 구간을 교대하는 모형이다. 25/50/75%는 목표 유지율이며,
Hamstring 성공·이동 경로에서 자동으로 계산한 추격 성능이 아니다. 각 조건 2,000회, seed 410으로 실행했다.

시전이 끊길 때 마나가 얼마나 소비되는지는 확정하지 않아 0%와 주문 비용의 100%를 각각 계산했다.
이 둘의 차이는 미확인 규칙에 대한 민감도이며, 통계적 신뢰구간이나 실제 승률의 하한·상한이 아니다.

| 목표 근접 유지율 | 끊긴 주문 마나 비용 | 30초: 승 / 패 / 미결판 | 60초: 승 / 패 / 미결판 |
| --- | --- | --- | --- |
| 25% | 0% | 0.0 / 0.2 / 99.8% | 0.0 / 0.2 / 99.8% |
| 50% | 0% | 0.0 / 0.1 / 99.9% | 0.0 / 0.1 / 99.9% |
| 75% | 0% | 0.0 / 0.1 / 100.0% | 0.1 / 0.1 / 99.9% |
| 25% | 100% | 0.0 / 0.0 / 100.0% | 0.3 / 0.0 / 99.7% |
| 50% | 100% | 0.1 / 0.0 / 99.9% | 3.5 / 0.0 / 96.5% |
| 75% | 100% | 0.5 / 0.0 / 99.5% | 11.8 / 0.0 / 88.2% |

반올림으로 합이 100%와 조금 다를 수 있다. 0.0%는 이 표본에서 처치가 없었다는 뜻이며 불가능하다는 뜻은 아니다.
동시 사망은 이번 표본에서 0건이다. 첫 사망 때 종료하므로 이후 예약된 폭발 피해로 발생할 사후 동시 사망은 포함하지 않는다.

**이 정책에서는 30초에 대부분 결판이 나지 않았고, 60초에도 생존과 상대 처치는 다르다.**
이 결과는 모형의 회복 정책이 작동한 경우다. 실제 첫 버스트를 붕대·포션으로 버틸 수 있다는 증거는 아니다.
TK → 포션 → MA만으로 회복하는 메이지를 빠르게 잡는 결과는 나오지 않았다.

#### 상대 정책을 바꾸면 달라지는 결과

다른 조건은 그대로 두고 상대가 공격 후 GH 몫을 남기지 않도록 바꾸면 아래처럼 상대 처치가 늘었다.
범위는 끊긴 주문 비용 0/100% 두 실험의 값이며, 실제 상대의 실력 차이를 측정한 값이 아니다.

| 목표 근접 유지율 | 60초 처치: 상대 예비 마나 11 | 60초 처치: 상대 예비 마나 0 |
| --- | --- | --- |
| 25% | 0.0\~0.3% | 1.1\~3.7% |
| 50% | 0.0\~3.5% | 11.9\~32.5% |
| 75% | 0.1\~11.8% | 24.6\~62.1% |

같은 스킬·스탯이어도 상대의 마나 관리 가정만으로 숫자가 크게 바뀐다.
이것이 이 값을 그대로 “내 승률”이라고 부를 수 없는 이유다.

#### 미확인 가정과 재현

- 폭발 퓨즈 2초, 근접이면 양쪽 Splashback 50/50은 모형의 가정이다. 실제 폭발 반경·투척 지연·회피 경로를 재현하지 않았다.
- 공식 피해·회복 범위 안에서 균등하게 추첨한다. AR·Resist 분포, 시전 중 재생, 서버 반올림은 실측하지 않았다.
- Poison·Curse·Paralyze·이동 방해·시야 차단·지형·후퇴·핑을 제외했다. 실제 메이지의 다양한 압박을 생략해 내 생존을 유리하게 볼 수 있다.
- 무기 장착은 즉시 적용되는 모형이며 실제 300ms 장비 조회·Dress 큐·걷기 제한은 재현하지 않았다.
  아이템과 시전 회복에는 200ms를 적용하고, 같은 tick에서는 시전 완료를 피해보다 먼저 처리한다.
- 필드 Hamstring의 이동 제한은 목표 근접 유지율에 포함한 가정이다. DEX 80의 조직 PvP 강화 피해를 필드에 추가하지 않는다.
- 버섯 마나 보충과 시폰의 PvM 효과는 제외한다. 실제 Razor·게임 서버·전투 로그로 보정한 모델이 아니다.

표의 입력·공식·정책은 [util/pvp-sim.mjs](https://github.com/minu-ha/uoo/blob/master/util/pvp-sim.mjs), 수치·일정 검사는
[util/pvp-sim.test.mjs](https://github.com/minu-ha/uoo/blob/master/util/pvp-sim.test.mjs)에 있다. Node 표준 라이브러리만 사용한다.
이 검사는 모형 계산을 확인하며 인게임 동작을 입증하지 않는다.

```
node --test util/pvp-sim.test.mjs
node util/pvp-sim.mjs --trials 2000 --output tmp/pvp-analysis/results.json
node util/pvp-sim.mjs --trials 2000 --mage-reserve 0 --output tmp/pvp-analysis/aggressive.json
```

### <a id="05.E"></a>05.E 던전에서 첫 버스트를 받는 경우

2026-10-05 사용자는 적 메이지 한 명의 TK → 폭발 포션 → Explosion → EB에 약 10초 안에 죽었다고 보고했다.
당시 Reflect는 없었고 몹에게 한두 대 맞아 HP는 약 100이었다. 정확한 피해별 시각과 상대 스킬은 확인되지 않았다.
최대 HP 120에서 네 단계가 모두 피해를 줬다고 계산하지 않는다. TK는 여기서 포션 부착을 준비하는 단계다.

상대 Magery·Eval 100, 주문 보조 상한 10%, Alchemy 120을 가정한다.
내 Resist 80, 반사·Splashback·중간 회복 없음에서 공식 범위를 대입한 예시는 다음과 같다.
Tracking과 Eval의 결합은 05.D절과 같은 공식 예시 해석이며, 서버 반올림·실측 분포를 확정한 값이 아니다.

| 피해 | 이 조건의 계산 범위 |
| --- | --- |
| Greater Explosion 포션 | 24\~40 |
| Explosion 주문 | 24.01\~39.69 |
| Energy Bolt 주문 | 24.01\~39.69 |
| 세 피해 합계 | 72.02\~119.38 |

HP 약 100에서는 이 세 피해만으로 사망할 수 있다. 이 계산은 보고를 설명할 수 있는 조건이지 실제 상대 스킬의 판정은 아니다.
각 범위의 중간값을 대입하면 합계 94.72지만 실측 평균이나 사망 확률로 해석하지 않는다.
Inscription 120은 스크롤 시전의 보조 상한을 채울 수 있으며, Tracking 등과 합쳐 상한을 초과하지 않는다.
따라서 Inscription 120이 없어도 위 피해량이 가능하다. 보정 정본은 [pvp.md](pvp.md#08) 08절이다.

Explosion 방출을 0초로 놓고 회복 0.2초 뒤 EB를 바로 시전하면,
EB 피해는 2.45초, Explosion 피해는 2.5초에 들어오는 일정이 가능하다.
이 약 0.05초 차이에 포션 폭발도 맞추면 HP가 한꺼번에 사라져 보인다.
실제 포션 퓨즈·투척 지연·핑을 맞춘 값은 아니다. 주문 시각의 정본은 [pvp.md](pvp.md#05.B) 05.B절이다.

#### 이 템플릿의 대응 순서

1. 노출 전에 Reflect와 HP를 준비한다. HP 100·Reflect 없음에서 공격 콤보부터 시작하면 첫 버스트를 버틸 여유가 작다.
2. 적 TK보다 먼저 자기 TK를 적용할 수 있으면 방어에 사용한다. 적 포션의 부착을 막는 선택이며 지면 폭발·Explosion·EB 면역은 아니다.
   적 TK가 이미 적용된 뒤 자기 TK로 제거할 수는 없다. 공격 TK와 공유하는 제한은 [pvp.md](pvp.md#04.C) 04.C절이다.
3. 적을 발견했는데 HP가 부족하면 모퉁이로 다음 주문의 시야를 끊고 즉시 회복할 기회를 만든다.
   이미 부착된 포션이나 방출된 Explosion이 사라졌다고 판단하지 않는다. 부착 포션은 가능하면 적에게 접근해 Splashback을 노릴 수 있지만,
   먼 거리·몹·퇴로를 무시하고 달라붙지는 않는다.
4. 상대가 실제 시전하는 순간의 MA·Harm 또는 도끼 명중으로 다음 주문을 끊는다.
   상대 Reflect와 주문 방해 창 때문에 MA 연타나 첫 한 방이 항상 시전을 끊는다고 기대하지 않는다.

#### 붕대 선행과 현재 자동 회복의 한계

Agility 후 DEX 100의 기본 자기 붕대는 10초 뒤 완료된다. 첫 피해를 받고 시작한 붕대는 몇 초 안에 겹치는 첫 버스트에 늦다.
미리 시작해 완료 시각을 앞당기는 생각은 유효하지만 붕대 자체가 즉시 HP나 피해 면역을 주는 것은 아니다.
공식의 정본은 [pvp.md](pvp.md#09.C) 09.C절이다.

이번 보고처럼 이미 HP 약 100이면 현재 스크립트의 붕대 시작 조건을 충족하므로 자기 MA로 추가 피해를 낼 이유가 없다.
진행 중 붕대가 없고 커서·시전 등의 대기가 없을 때 요청하는지는 인게임에서 확인한다.
만피에서는 현재 스크립트가 붕대를 요청하지 않으며, 서버가 만피 자기 붕대를 허용하는지는 확인되지 않았다.
자기 MA는 매회 마나 4를 쓰고 반복 피격으로 진행 중 붕대가 미끄러질 수 있으므로 자동 반복을 추가하지 않는다.

보고 당시 v4는 기본 힐 포션 손실 35, GH 손실 45와 수동 입력 보류 정책을 사용했다.
최대 HP 120 중 100은 두 회복 요청의 시작값에 도달하지 않았다.
v5는 GH를 손실 35로 앞당기고 준비된 긴급 회복이 있으면 수동 주문을 중단한다.
다만 아직 피해가 없거나 중립 커서를 들고 있으면 자동으로 다음 버스트를 예측해 회복하지 않는다.
공식 포션 동작과 현재 정책은 각각 [pvp.md](pvp.md#05.B) 05.B절과 [05.E절](pvp.md#05.E)이다.
HP 기준을 높이는 것만으로 거의 동시에 들어오는 모든 피해를 방어할 수는 없다.

### <a id="06.A"></a>06.A 점화한 포션의 실패 처리

- 실패·취소가 퓨즈를 초기화하지 않는다고 보고 추가 점화를 막는다. 소유권·잔여 퓨즈·지면 투척 결과가 불명확하면 경고와 회피가 필요하다.

## <a id="07"></a>07 Eval을 뺀 비용과 근접 한 대

다음은 실측 피해나 승률이 아니라 비교용 계산이다. 스킬·상대 방어·명중·회복을 분리한다.
Tracking 주문 보조의 결합 순서를 단정하지 않기 위해 첫 표에서는 양쪽 모두 제외했다.

Magery 80, 상대 Resist 100의 피해 감소를 예시로 25% 적용하고 주문 기본 피해의 중간값을 사용한다.
`피해 예시 = 기본 피해 × 0.8 × (0.75 + 0.375 × Eval / 100) × 0.75`.
25%는 비교를 위한 가정이지 모든 타격의 고정 저항률이 아니다 ([pvp.md](pvp.md#08) 08절).

| 주문 | Eval 0 | Eval 100 | 차이 |
| --- | --- | --- | --- |
| MA, 기본 중간값 6 | 2.70 | 4.05 | 1.35 |
| Explosion 또는 EB, 기본 중간값 32 | 14.40 | 21.60 | 7.20 |
| Explosion + EB | 28.80 | 43.20 | 14.40 |

같은 Magery라면 이 모델에서 Eval 100은 Eval 0의 1.5배다. 차이가 없는 것이 아니다.
Magery 100·Eval 100 메이지와 비교하면 1.875배다. 둘 다 다른 보정을 제외한 비교다.

근접 예시는 일반 무기, Tactics 100·Anatomy 80·도끼 보조 상한 20%, 상대 AR 50, Parry·Reactive Armor·추가 장비 보정 없음으로 잡는다.
`피해 = 무기 기본 피해 × (1 + 0.16 + 0.20) × (1 − 방어구 감소율)`.
AR의 감소식은 [pvp.md](pvp.md#09.E) 09.E절이다.

| 무기 | 명중했을 때 계산 범위 | 기본 피해·감소율 중간값의 예시 | 명중률 50%를 곱한 스윙당 예시 |
| --- | --- | --- | --- |
| Great Axe | 19.05\~52.14 | 34.18 | 17.09 |
| Norse Axe | 11.79\~26.07 | 18.37 | 9.18 |

Alchemy 0의 Greater Explosion 포션 15\~25까지 더하면 포션 + Great Axe 한 대 + Norse Axe 한 대가 모두 명중한 합은 약 45.84\~103.22다.
상대 회복·추가 방어·Splashback·빗나감·접근 실패를 뺀 합이므로 확정 콤보 피해나 DPS로 쓰지 않는다.

상대가 Inscription 100의 Reactive Armor를 유지하고 남은 방어량도 충분하다면,
위 근접 중간값 예시에 0.75를 추가 적용해 Great Axe 약 25.64, Norse Axe 약 13.77로 내려간다.
방어량이 도중에 소진되는 타격까지 이 감소율이 그대로 유지된다고 가정하지 않는다 ([pvp.md](pvp.md#05) 05절).

이 예시에서는 **추가로 맞힌** 근접 한 대가 Eval로 늘어나는 두 주문의 차이를 넘을 수 있다.
하지만 명중·접근이 보장되지 않고, Eval 100을 얻으려면 다른 스킬 100점을 빼야 한다.
두 빌드가 원래 둘 다 때릴 한 대를 한쪽에만 더해 유리하다고 계산하지 않는다.

### <a id="08.B"></a>08.B 채집 근거

> Lumberjacking always uses Smart Harvest

[공식 Lumberjacking 문서](https://wiki.uooutlands.com/Lumberjacking)는 장착한 Hatchet의 더블클릭으로 주변 나무를 채집한다고 설명한다.
v4에서 도구 사용 뒤 커서만 남는 화면을 받았다. v5는 기존 `lumberjack.razor`의
`Use item in hand` → 커서 대기 → `Target Self` 순서를 사용한다.
[공식 Smart Harvest 문서](https://wiki.uooutlands.com/Smart_Harvest)도 도구 사용 뒤 자신이나 상태바를 타깃하는 경로를 설명한다.
손의 Hatchet을 확인한 뒤 사용하며, 기존 수동 커서가 있으면 새 채집을 시작하지 않는다.
v7은 현재 클라이언트의 `dress serial` 실패 보고에 따라
`lift` → `drop self lefthand`로 장착하고 다음 시도에서 손을 다시 확인한다.
Hatchet은 [공식 무기 표](https://wiki.uooutlands.com/Template:SwordsWeaponClass)에서 2H다.
[UO의 양손 장비 레이어는 0x02](https://github.com/ServUO/ServUO/blob/pub57/Server/Item.cs)이며,
[Razor는 이를 LeftHand로 부른다](https://github.com/markdwags/Razor/blob/master/Razor/Core/Item.cs).
v9에서 빈손인데 백팩 Hatchet을 장착하지 않는다는 사용자 보고를 받았다. 인게임 확인됨 2026-10-05.
`findtype … self`의 실제 검색 범위나 실패한 가드까지 확인한 것은 아니므로, `lefthand` 문법 오류라고 단정하지 않는다.
v10은 [bard-mace](https://github.com/minu-ha/uoo/blob/master/script/archive/bard-mace.razor)처럼 `lhandempty`를 먼저 읽고,
저장한 `var__my_hatchet`을 백팩에서 찾아 `lift` → `drop self lefthand`로 장착한다.
장착 다음 시도에서는 `findlayer self lefthand`의 serial이 저장한 도끼와 같은 경우에만 사용한다.
검색 성공이나 장착 요청을 실제 장착으로 취급하지 않는다. 다른 왼손 장비만 비우며 오른손 무기 처리는 수동 장비 핫키에 맡긴다.
주변 나무 선택은 Smart Harvest가 맡으며 개별 나무 검색은 넣지 않는다.
공식 문구만으로 한 번의 요청이 고갈까지 계속 도는지 확정하지 않는다. 기본 명령 재시도는 커서 처리 뒤 4초다.
v15는 주변 채집 자원이 없다는 응답을 읽으면 다음 시도만 2초로 예약한다. 다음 요청부터 기본 간격으로 돌아간다.
이 응답은 Tracking·리콜 감지 뒤에 읽으며, 대기 중 회복 루프와 수동 입력·리콜 차단 조건은 유지한다.
v8의 기본 채집은 사용자가 정상 작동을 보고했다. 인게임 확인됨 2026-10-05.
v10의 빈손 장착·serial 확인 경로는 아직 확인되지 않았다.
v13의 END와 이후 채집 응답은 사용자 Journal에서 확인했다. 인게임 확인됨 2026-10-05.
목재 이동 전체의 완료와 v14의 파우치 제외는 아직 확인되지 않았다.

> they will have a 60 second delay before they can attempt to Harvest again

같은 문서는 Recall·Moongate·Hike 뒤의 채집 제한을 60초로 명시하고 Teleport·Rope에도 적용한다고 덧붙인다.
**60초는 확인된 서버 규칙이다.** 스크립트가 이동 성공 시각이나 서버의 남은 시간을 읽는 것은 별개의 문제다.
이동 거절 안내는 두 프로필에서 `[ harvest, wait ]`로 표시하고 스크립트에서는 조회하지 않는다.
4초는 현재 채집 명령의 재시도 간격이며, 서버의 60초 제한을 줄이거나 대체하지 않는다.
거절 안내를 받은 시점부터 새 60초 대기를 시작하는 타이머도 없다. 매핑은 [overheads.md](overheads.md#07) 07절에 있다.

상태 표의 축약 이름도 `var__` 접두를 쓴다. 주기는 클라이언트 재시도 값이며 서버 남은 시간의 측정값이 아니다.
회복·버프의 대기는 기존 `casting`과 제한된 반복으로 처리하고, 끊김 메시지를 별도로 소비하지 않는다.
메인 루프에서는 Tracking 감지보다 앞에서 메시지를 소비하지 않는다.
시작 설정에서 Hunting을 멈추고 필터를 확인한 뒤에는 `clearsysmsg`로 이전·중간 필터의 메시지를 비운다.

리콜 감지는 채집 전에 읽으므로 발견된 경보는 같은 패스의 채집·정리를 보류한다.
채집의 3초 커서 대기나 목재 정리 중 새로 도착한 경보는 다음 패스에서 읽으며,
해당 동작 중 계속 감지하는 것은 아니다. 시약 부족은 리콜 감지 뒤에 읽고 같은 패스에서 시약을 다시 읽는다.
목재는 각 가공·이동 요청 사이에서 회복·수동 입력·큐 상태를 다시 확인한다.
단계별 시간 예산이 끝나면 남은 목재는 다음 정리 주기로 넘겨 생존·채집 점검으로 돌아간다.

2026-10-05 사용자가 목재 가공·파우치 이동 성공 뒤 다른 Logs가 남고 채집이 멈춘다고 보고했다.
화면에는 가공 성공 문구가 있으며 `Script Error`와 줄 번호는 확인되지 않았다.
Play 상태라는 보고만으로 오류 위치를 확정하지 않는다. 기존 코드는 전체 스택 처리가 끝날 때까지 메인 루프로 돌아오지 않고,
`queued`가 남으면 다음 스택부터 처리를 중단하는 조건이 있었다.
현재 v15의 sysmsg 기록은 `Lumber pack BEGIN` → 가공·`Lumber skip`·`Lumber move request` → `Lumber pack END`다.
`skip: … already in pouch`는 기존 Boards를 들어 올리지 않았다는 판별 기록이다.
`move request`는 lift/drop 직전 요청 기록이며 서버 이동·병합 성공을 보증하지 않는다.
같은 hue의 새 Boards가 기존 묶음에 합쳐지면 원래 파우치 묶음의 serial이 유지될 수 있으므로 요청한 serial이 사라져도 실패로 단정하지 않는다.
기존 파우치 묶음 자체를 다시 이동시켜 합치는 로직은 없다. 실제 병합 결과·용량·서버 응답은 인벤토리에서 확인한다.
END 뒤에도 채집이 보류되면 큐·커서 안내와 리콜·책·Hunting 조건을 함께 확인한다.
남은 확인은 [open-items.md](open-items.md#09) 09절에 있다.

### <a id="08.D"></a>08.D 실행 준비와 인게임 확인

1. Tracking 감지 리콜을 사용할 때 Tracking 창의 Hunt Frequency를 **Always Get Closest**로 둔다.
   스크립트는 대상 필터를 맞추지만 추적 빈도 모드를 바꾸지는 않는다.
   공식 모드의 차이는 [Tracking 문서](https://wiki.uooutlands.com/Tracking)의 Hunting 항목을 본다.
2. 레시피가 `escape/recall`을 쓰면 충전한 책에 `Home` 룬을 준비한다.
   다른 이름이면 파일의 `say "[RecallCharge Home"` 한 줄을 바꾼다.
   명령 의미는 [공식 Commands 문서](https://wiki.uooutlands.com/Commands)의 RecallCharge 항목에 있다.
3. Hatchet·붕대·시약·포션을 넣고 `Use item in hand`, `Bandage Self`, 각 Drink 핫키,
   `> Smart Heal/Cure Self`, `> Greater Heal/Cure Self`, `> Interrupt`,
   `Cancel Current Target`가 현재 캐릭터에서 동작하는지 확인한다.
4. 백팩 안의 파우치를 준비한다. 파우치가 정해지지 않았거나 백팩에 없으면 시작 시 `[ loot pouch, pick ]`이 뜨고, 한 번 선택한다.
   이미 `loadout`으로 지정했다면 그 값을 사용한다. 실행 중 파우치가 없으면 `[ loot pouch, out ]`을 표시하고 정리는 건너뛴다.
5. 현재 캐릭터의 `heal pot`, `walk`, `reflect` 바를 확인한다.
   없는 바는 0으로 보이므로 이동 차단과 Reflect 재시전 제한을 보호하지 못한다. 설정 변경은 별도 작업이다.

## <a id="09"></a>09 공통 pvp의 마법·무기·붕대 설정

[combat/pvp.razor](https://github.com/minu-ha/uoo/blob/master/script/combat/pvp.razor)의 독립 옵션으로
공통 [PvP 자기관리 루프](pvp.md#05.E)를 사용한다.
채집 enhanced를 멈추고 `Play Script: combat\pvp`에 연결한 별도 핫키로 전환한다.
이전 템플릿별 PvP 파일과 프리셋 분기는 삭제했고 본문 하나에서 설정한다.

### <a id="09.A"></a>09.A 수동 공격과 자동 회복·장착

Q 대상 선택·Tab·근접 공격 요청·Hamstring·MA/Harm·TK·폭발 포션·Teleport·Rope는 수동이다.
상대 noto 필터·거리 검색·사망 조회·공격 재요청은 없다. 서버에 이미 남아 있는 자동공격·반격은 사용자가 제어한다.

자기 파우치·큐어·힐·Refresh·Strength/Agility 포션, Healing이 있으면 붕대,
큰 피해의 GH와 해독·붕대 부족 시 Heal을 자동으로 처리한다.
무기 옵션을 켜면 시전·커서가 없을 때 스윙 바를 읽고 Great Axe/Norse를 자동 장착한다.
준비된 무기와 빈손 재장착의 순서는 공통 문서 05.E절을 따른다. 무기를 들었다고 새 공격 요청을 보내지는 않는다.

Warmode ON/OFF와 상대 선택 여부에 상관없이 자기 상태만 본다.
평소 수동 시전·커서는 기다리지만, 준비된 긴급 회복은 수동 주문을 중단하고 먼저 사용한다.
만피에서 다음 붕대를 준비하는 자기 MA는 수동으로 남긴다. 기준과 입력 경합의 한계는 공통 문서 05.E절을 따른다.

### <a id="09.B"></a>09.B 독립 설정

마법과 붕대는 `config__use_magery`·`config__use_bandages`가 기본 1이고, 무기 교체는 레시피의 `fight/weapon-swap` 블록이 맡는다.
지금 pvp에는 셋이 모두 들어 있다. Magery가 없는 템플릿은 Magery만 0으로 바꾼다.
회복 마나와 자원을 남기려면 RA·Reflect·Resist 포션 중 불필요한 옵션을 각각 0으로 끈다.
시폰용 자기 MA와 버섯의 자동화 옵션은 제거했다.
한 기능을 바꾸어도 다른 기능의 설정은 덮어쓰지 않는다.

이 도끼 조합은 `swing 4`에 Great Axe, `swing 1`에 Norse Axe를 연결한다.
바 시간은 현재 STA의 [03절 계산](#03)과 비교해 활성 클라이언트에서 맞춘다.
빠른 스윙으로 큰 한 방의 시점이 밀릴 수 있으므로, 그 시점을 수동으로 고르고 싶으면 무기 옵션을 끈다.
슬롯 ID·충돌 장비 해제·회복 임계값·상태·타이머의 정본은 공통 문서 05.E절이다.

### <a id="09.C"></a>09.C 인게임 반영과 확인
